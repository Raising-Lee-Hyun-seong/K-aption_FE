# K-aption FE

영어 강의 파일을 선택하고 한국어·영어 자막과 함께 재생하는 React 프론트엔드입니다. 현재는 **목 데이터로 화면과 사용자 흐름을 시연하는 단계**입니다. 업로드한 파일의 음성을 인식하거나 번역하지 않으며, 백엔드로 HTTP 요청을 보내지 않습니다.

- 저장소: https://github.com/Raising-Lee-Hyun-seong/K-aption_FE
- 기술 스택: React, TypeScript, Vite
- 백엔드 저장소: https://github.com/Raising-Lee-Hyun-seong/K-aption_BE
- 실행 환경: Node.js와 npm이 설치된 PC의 최신 브라우저

## 현재 범위

| 기능 | 상태 |
| --- | --- |
| MP4·MKV·MP3·WAV 선택 및 드래그 앤 드롭 | 프론트엔드 구현 |
| 파일 형식·빈 파일·90분 초과 검사 | 프론트엔드 구현. 길이는 브라우저가 읽을 수 있을 때 검사 |
| 강의 용어집 선택 | 데모 UI. 실제 파일 처리에는 적용되지 않음 |
| 음성 추출 → 영어 음성 인식 → 문맥·용어집 처리 → 한국어 번역 → 자막 생성 | 목 단계·목 진행률 표시 |
| 로컬 영상·음성 재생 | 브라우저에서 재생 가능한 파일에 한해 구현 |
| 한국어·English·한·영 자막 전환, 현재 구간 강조, 카드 클릭 이동 | 고정 목 자막으로 구현 |
| 일부 번역 실패·자막 없음·처리 실패 시연 | 목 결과 선택으로 구현 |
| 실제 STT·번역 API 연결 | 후속 작업 |
| 작업 저장·재방문 복원·SRT/VTT 다운로드·용어집 편집 | 미구현 |

화면 상단의 **데모 · 실제 AI 처리 아님** 표시는 진행률과 자막이 실제 처리 결과가 아님을 알립니다. 목 자막은 업로드한 강의 내용과 관계없이 고정된 예시 문장입니다.

## 실행 준비

프로젝트 루트에서 실행합니다. 처음 실행할 때는 의존성을 설치합니다.

```powershell
git clone https://github.com/Raising-Lee-Hyun-seong/K-aption_FE.git
cd K-aption_FE
npm ci
npm run dev
```

터미널에 표시된 주소를 브라우저에서 엽니다. 기본 주소는 `http://localhost:5173/`입니다. VS Code에서는 프로젝트 폴더를 열고 **터미널 → 새 터미널**에서 같은 명령을 실행할 수 있습니다. 개발 서버는 터미널에서 `Ctrl+C`로 종료합니다.

| 명령 | 용도 |
| --- | --- |
| `npm run dev` | Vite 개발 서버 실행 |
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm run build` | 타입 검사 후 `dist/`에 배포용 정적 파일 생성 |

`node_modules/`, `dist/`, TypeScript 빌드 캐시는 Git에서 제외합니다.

## 화면과 사용 흐름

1. **업로드(U-01):** 파일 선택 버튼, 드래그 앤 드롭 또는 키보드 Enter/Space로 파일을 고릅니다. 확장자는 `mp4`, `mkv`, `mp3`, `wav`만 허용합니다. 브라우저가 재생 길이를 읽으면 90분 초과 파일을 시작 전에 거부합니다.
2. **처리 중(U-02):** `번역 시작`을 누르면 다섯 단계와 데모 진행률이 순서대로 표시됩니다. 이 단계는 실제 파일 분석이나 서버 작업이 아닙니다. 브라우저 탭을 닫으면 작업이 유지되지 않습니다.
3. **오류(U-03):** 지원하지 않는 형식, 빈 파일, 확인된 90분 초과, 선택한 데모 처리 실패를 안내합니다. `다시 올리기`로 업로드 화면으로 돌아갑니다.
4. **재생(U-04):** 선택한 로컬 파일을 현재 탭에서 재생합니다. 재생 위치에 따라 목 자막과 목록 강조가 바뀝니다. 언어 버튼으로 한국어·English·한·영을 전환하고 자막 카드를 누르면 해당 시점으로 이동합니다. 상단 `K` 아이콘은 업로드 홈으로 돌아갑니다.

업로드 화면의 **데모 결과** 선택에서 정상 완료, 일부 번역 실패, 자막 없음, 처리 실패를 시연할 수 있습니다. 일부 번역 실패 구간은 영어 원문과 `번역 실패 · 원문 유지` 배지를 표시합니다. 자막 없음 결과에서도 재생 조작은 유지됩니다.

## 파일 및 브라우저 동작

- `accept` 속성과 별도로 파일 확장자를 검사합니다. 파일 내용의 최종 검증은 아직 서버에 연결되지 않았습니다.
- 브라우저가 재생 길이를 읽지 못하면 90분 제한을 확인할 수 없다는 안내를 표시하고 데모를 계속할 수 있습니다.
- 선택한 파일은 `URL.createObjectURL`로 **현재 탭에서만** 재생합니다. 홈으로 돌아가거나 페이지가 종료되면 URL을 해제합니다. 파일은 서버에 저장되지 않습니다.
- MKV 등 일부 파일은 확장자가 허용되어도 브라우저의 코덱 지원 여부에 따라 재생되지 않을 수 있습니다. 이때 재생 오류 안내와 자막 목록을 표시합니다.
- 새로고침하면 선택 파일과 목 작업 상태가 사라집니다.

## 데이터 경계와 백엔드 연결

화면은 `src/types.ts`의 `ApiClient`, `JobView`, `SubtitleSegment`를 사용합니다. 현재 구현된 어댑터는 `src/api/mockAdapter.ts` 하나이며 메모리에서 목 작업 상태와 고정 자막을 반환합니다. `src/App.tsx`에는 실제 API 요청 코드가 없습니다.

| 파일 | 역할 |
| --- | --- |
| `src/App.tsx` | 업로드·처리·오류·재생 화면과 로컬 UI 상태 |
| `src/api/mockAdapter.ts` | 데모 단계·진행률·자막·오류 결과 |
| `src/types.ts` | 화면과 어댑터가 공유하는 타입·인터페이스 |
| `src/styles.css` | 디자인 토큰, 데스크톱·모바일 레이아웃 |

현재 BE의 연동 가능한 경로는 `POST /api/v1/transcriptions?language=en`입니다. 요청이 끝난 뒤 `segments` 배열을 반환하는 **동기 API**이므로 실제 연동 시 목 단계 완료나 퍼센트를 서버 진행률처럼 표시해서는 안 됩니다. 응답의 `start`·`end`는 초 단위이며 화면의 `startMs`·`endMs`로 변환해야 합니다. `translation=null` 또는 `translation_error=translation_failed`인 구간은 영어 원문을 유지하고 실패 상태를 표시해야 합니다. `segments=[]`는 음성 없음 상태로 다룹니다. 현재 BE에는 작업 ID·진행률 조회·원본 미디어 저장 URL·용어집 선택 API가 없습니다.

실제 API 연동은 별도 어댑터에서 `FormData(file)` 요청, 응답 정규화, HTTP 415·422·500 및 네트워크 오류 처리를 구현한 뒤 진행합니다. 브라우저가 multipart 경계값을 설정하도록 `Content-Type`을 직접 지정하지 않습니다. 백엔드 주소는 환경 변수로 관리해야 하며, 지금 코드에는 백엔드 주소나 요청이 없습니다.

## 검증과 다음 작업

```powershell
npm run typecheck
npm run build
```

타입 검사와 Vite 빌드가 통과하는 것을 확인했습니다. 데스크톱 업로드 화면은 제공된 UI 와이어프레임과 비교했습니다. 실제 미디어·브라우저 조합에서의 재생과 접근성은 추가 수동 검증이 필요합니다.

다음 단계는 BE 동기 API용 어댑터와 오류 정규화를 추가하고, 실제 영어·한국어 구간으로 재생을 확인하는 것입니다. 백엔드가 작업 ID 기반 비동기 처리, 저장, 다운로드 및 용어집 API를 제공하면 해당 기능의 UI를 연결할 수 있습니다.
